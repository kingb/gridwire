# Grid projection conformance corpus

The **cross-producer** corpus for the neutral grid (`gridwire`). Every producer
of a `GridDelta` from a byte stream — a session backend's engine projection, a terminal
frontend's local PTY projection — must turn the same input into the same delta.
It is the grid crate's substitute for the registry corpus's two-language proof:
same shape, different axis (two producers, one corpus, every case agrees).

## Layout

- `<name>.json` — input, one of two shapes (exactly one of `feed`/`steps`):
  - **single drain:** `{"dims": {"columns": C, "screen_lines": R}, "feed": "<bytes>"}`
    — feed the bytes and drain once.
  - **multi drain:** `{"dims": {…}, "steps": ["<bytes>", "<bytes>", …]}` — feed
    each chunk and drain after each. Exercises mid-stream transitions (e.g. an
    incremental drain followed by a reset).

  `feed`/each `step` is a JSON string decoded to UTF-8 bytes; a control byte such
  as ESC is written as its JSON unicode escape (ESC is the six characters
  backslash, `u`, `0`, `0`, `1`, `b`).
- `<name>.expect.json` — the expected output: a single `GridDelta` for a `feed`
  case, or an **array** of `GridDelta` (one per step) for a `steps` case. The
  producer's drained delta(s) must equal it.

Grids are kept tiny so the expected frame is small and hand-verifiable.

## Provenance

The `.expect.json` files were generated by one producer's alacritty-based projection
and hand-verified. `gridwire`'s own test has no VT engine, so it checks only that
each fixture is **well-formed** against the wire types — it cannot assert
agreement itself (no VT engine allowed here).

**Cross-producer agreement — a manual run, confirmed for all seven cases
(2026-09-11).** A second producer, the terminal frontend's local
`AlacrittyProjection`, was fed the exact bytes of every fixture (including the
multi-drain `steps` case) and its output diffed against these `.expect.json`
byte-for-byte — the resolved SGR-31 RGB, the wide-char leader/spacer/style split,
the grapheme cluster, alt-screen entry, and the reset-mid-stream sequence all
matched. So every case here is **agreement**, not merely well-formedness.

That was a **one-time manual run**, not a standing guarantee. It becomes permanent
only once each producer's CI consumes `conformance/grid/` and asserts the match on
every run (adopting it into each producer's CI is a separate decision, not assumed
here). New cases are "well-formed" until a second producer has run them too.

## Adding a case

Add the input and its `.expect.json` together — a runner fails on an unpaired
input, so a case cannot slip through half-specified.

## Coverage

Coverage:

- `plain-text` — redraw.
- `wide-char` — wide-glyph leader + `WideSpacer`.
- `sgr-red` — SGR → `Attrs` / concrete-RGB + style interning.
- `grapheme-cluster` — base + combining mark folded into `CellContent::Cluster`.
- `alt-screen` — alternate-screen entry sets `alt_screen`.
- `reset-mid-stream` — a `steps` case: reset → **incremental** → reset (the
  alt-screen switch), proving `reset` is not universal per drain.
- `reset-style-carry` — **enforces** the complete-style-table rule: a style is set
  (red `A`), then a reset (alt-screen) paints a same-style cell (red `B`). The
  reset's `.expect.json` re-carries that style in `new_styles` even though it was
  first seen before the reset, so a producer that ships only newly-interned styles
  on a reset **fails conformance** here — rather than being silently rescued by a
  consumer's `merge` carry-forward. The safety net is the second line; this is the
  contract.

Cross-producer agreement has been manually confirmed for **all seven** cases,
`reset-style-carry` included — a second producer ran both of its steps and
matched, and step 2 is the real test: the style is interned in step 1, so a
producer only passes by re-shipping the complete table on the reset (satisfying
the invariant) rather than being rescued by a consumer's carry-forward.
